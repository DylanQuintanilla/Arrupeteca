Orden Paso a Paso: Ciclo de Vida de las Clases

Sigue este camino lineal para rastrear el flujo de ejecución completo en el código

FASE 1

Arranque e Inicialización del Sistema (Bootstrap)

Al iniciar la aplicación Spring Boot (`ArrupetecaApplication`), el contenedor levanta en primer lugar la configuración de seguridad y la base de datos:

1.1
application.properties JwtConfig.java

Spring lee las variables `jwt.secret`, `jwt.access-token-expiration` (24 horas) y `jwt.issuer` de los properties y las inyecta en la clase de configuración JwtConfig.

1.2
SecurityConfig.java

Se construye el Bean SecurityFilterChain: desactiva CSRF, configura sesiones STATELESS, habilita CORS para http://localhost:5173, registra los endpoints públicos (/api/auth/**, Swagger) y conecta el filtro JwtAuthenticationFilter.

1.3
data.sql

Se ejecuta el script de semillas insertando en MySQL los tipos de usuario por defecto: admin, alumno, maestro, personal administrativo.

FASE 2

Flujo de Registro de Usuario (`POST /api/auth/register`)

Cuando un administrador o usuario se registra en la aplicación:

1. Cliente (React) RegisterRequest AuthController.java

El cliente envía un JSON a POST /api/auth/register. AuthController.register(@Valid RegisterRequest request) recibe la petición y llama inmediatamente a authService.register(request).

2. AuthServiceImpl.java UsuarioRepository & TipoUsuarioRepository

AuthServiceImpl verifica si el correo ya existe en usuarioRepository.existsByCorreo(). Luego busca el rol en tipoUsuarioRepository.findById(request.idTipo()).

3. PasswordEncoder (BCrypt) Usuario.java (Entidad)

La contraseña se encripta con passwordEncoder.encode(contrasena). Se construye la entidad Usuario y se guarda en la base de datos con usuarioRepository.save().

4. JwtService.java AuthResponse Cliente

AuthServiceImpl invoca a jwtService.generateToken(usuarioGuardado). Se genera un token JWT firmado con claims del rol y correo. Se retorna al controlador y este responde con un HTTP 201 y ApiResponse.exito(..., authResponse).

FASE 3

Flujo de Inicio de Sesión / Login (`POST /api/auth/login`)

Secuencia exacta cuando un usuario inicia sesión con correo y contraseña:

1. AuthController
Recibe LoginRequest
2. AuthServiceImpl
authenticationManager.authenticate()
3. CustomUserDetailsService
loadUserByUsername()
4. BCrypt Match
Verifica Hashing
5. JwtService
Genera Token 24h
¿Qué ocurre internamente en la autenticación?
  • AuthenticationManager delega la verificación a DaoAuthenticationProvider.
  • DaoAuthenticationProvider consulta a CustomUserDetailsService, el cual busca en UsuarioRepository.findByCorreoAndBorradoLogicoFalse(correo).
  • Si las credenciales son válidas, AuthServiceImpl actualiza ultimaFechaActividad = LocalDateTime.now().
  • Se llama a JwtService.generateToken(usuario) y se retorna el Bearer Token de 24 horas.
FASE 4

Flujo de Petición Protegida y Auditoría (ej. `GET /api/v1/libros`)

Cuando el cliente realiza cualquier petición enviando la cabecera Authorization: Bearer <token>:

1. Petición HTTP con Header Authorization JwtAuthenticationFilter.java

Antes de llegar al controlador, la petición es interceptada por JwtAuthenticationFilter.doFilterInternal(). Extrae el substring después de "Bearer ".

2. JwtAuthenticationFilter JwtService.java

El filtro invoca jwtService.extractUsername(token). JwtService valida la firma digital HMAC con la clave secreta en JwtConfig y verifica que el token no haya expirado (24h).

3. JwtAuthenticationFilter SecurityContextHolder

Si el token es válido, se crea un objeto UsernamePasswordAuthenticationToken con los roles del usuario y se inyecta en SecurityContextHolder.getContext().setAuthentication(...).

4. Controlador REST (ej. LibroController) JpaConfig.java (AuditorAware)

La petición entra al controlador. Si el servicio guarda o edita un registro auditado (Auditable), JpaConfig.auditorProvider() consulta SecurityContextHolder e inyecta automáticamente el correo del usuario en creadoPor y actualizadoPor.

FASE 5

Manejo de Errores y Excepciones de Seguridad

¿Qué ocurre en el flujo si algo falla o el usuario no tiene permisos?

Sin Token / Token Inválido
JwtAuthenticationEntryPoint

Intercepta la falla en autenticación y retorna un HTTP 401 Unauthorized con JSON uniforme de ApiResponse.

Credenciales Incorrectas
GlobalExceptionHandler

Captura BadCredentialsException y responde con HTTP 401 Unauthorized: "Credenciales inválidas".

Sin Rol Necesario
GlobalExceptionHandler

Captura AccessDeniedException y responde con HTTP 403 Forbidden: "No tiene permisos suficientes".

8 JwtAuthenticationFilter.java com.arrupeteca.security Filtro HTTP Intercepta peticiones protegidas y coloca la autenticación en `SecurityContextHolder`.
9 JpaConfig.java com.arrupeteca.config Auditoría JPA Obtiene el usuario de `SecurityContextHolder` para llenar `creadoPor` y `actualizadoPor`.
10 JwtAuthenticationEntryPoint.java com.arrupeteca.security Manejo Excepciones Responde con JSON `401 Unauthorized` si el token falta o es inválido.
